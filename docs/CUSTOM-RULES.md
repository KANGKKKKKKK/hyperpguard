# 自定义规则使用说明

自定义规则是给内置规则打补丁用的：内置表里没有的域名、或者只想拦域下某个路径时，用它临时补上，不用等发版。

它只作用于**网络出口**这一层，不改变方法层、Provider、AIDL、数据库写入的行为。

## 一、格式

入口：应用主界面 →「自定义规则」→ 输入框填写 →「添加」。

支持两种写法：

| 写法 | 例子 | 作用 |
|---|---|---|
| 域名 | `tracking.example.com` | 拦该域名及其所有子域 |
| 域名/路径 | `api.example.com/track/` | 只拦路径以 `/track/` 开头的请求 |

- 输入框只接受字母、数字、点、下划线、连字符，所以不支持通配符 `*`、正则、端口、协议头；
- 多条规则用界面上依次「添加」即可，内部以 `;;` 分隔；
- 「清空」删除全部自定义规则。

## 二、匹配方式

- **域名**：`host == 规则` 或 `host` 以 `.规则` 结尾。写 `example.com` 会同时命中 `a.example.com`，但不会命中 `notexample.com`。
- **路径**：`path.startsWith(规则路径)`，只做前缀匹配，不做全路径包含匹配；仅对走 `URL#openConnection` 的请求有效（`InetAddress`、`Socket` 拿不到路径）。
- **大小写**：匹配前统一转小写，规则写 `Tracking.Example.com` 也能用。
- **IP 直连**：host 就是 IP 字面量，需要把 IP 原样写进规则。
- 路径规则受「路径特征拦截」开关控制（默认开启）；关掉后带路径的规则整条不匹配（不会退化成按域名拦），需要按域名拦就另加一条纯域名规则；
- 某个包开着「整进程断网」时按整进程处理，规则表不参与匹配。

拦截生效的入口共四处，规则对它们一致：

| 入口 | 能否拿到路径 |
|---|---|
| `URL#openConnection` | 是 |
| `InetAddress#getByName` / `getAllByName` | 否 |
| okhttp `Dns#lookup` 的自定义实现 | 否 |
| `Socket` 构造 / `connect` | 否 |

## 三、生效范围

- 只对被注入的作用域包生效。不在 LSPosed 作用域里的进程完全不受自定义规则影响。
- 规则会追加到每个作用域包自己的规则列表后面，不受内置开关状态影响：把某个应用的内置子项全关掉，自定义规则照样生效。
- 例外：`com.miui.guardprovider`、`com.miui.misightservice`、`com.xiaomi.trustservice`、`com.xiaomi.aiasst.vision` 这四个包只在自身内置规则非空时才装载网络层，内置子项全关时自定义规则也不会装。其余作用域包无此限制。

## 四、生效时机

规则在进程注入时读取一次。添加或删除规则后，**必须重启对应应用**（界面上的「重启」按钮或批量「全部重启」）才会重新读取，不重启等于没改。

## 五、怎么确认命中

查看日志，命中会有两种前缀：

```
X(host) api.example.com
X(host+path) api.example.com/track/v1
```

没命中但确实发生了请求时，可以先打开「记录未拦截访问」，跑一段时间后日志里会出现：

```
? securitycenter tracking.example.com
```

`?` 开头的记录就是「访问了但没被任何规则拦下」的域名，把它填进自定义规则即可。这个开关会持续写日志，补齐规则后建议关掉。

## 六、做不到的事

- 拦不到 native 层的连接（cronet、自家 `.so` 里的 socket）、WebView 的 native 网络栈，以及已经建立好的长连接；
- 拦不到本地数据流：数据库写入、Provider 查询、AIDL 调用、方法调用都不在网络层，自定义规则管不到；
- 不能跨作用域生效，也不能按包名限定只对某一个应用生效（规则对全部作用域包一律追加）；
- 不支持通配符和正则，多域名需要逐条添加。

## 七、存储位置

- 界面写入 `SharedPreferences`（键 `custom_rules`），同时同步到 `Settings.Global` 的 `hyperpguard_conf`，值经过 URL 编码；
- 目标进程启动时只读 `hyperpguard_conf`，本地偏好只是界面自己的副本；
- 清除模块数据不会让规则失效：`hyperpguard_conf` 里那份还在，界面会回落到它读回来。要真正清掉，用界面「清空」按钮；
- 如果界面显示条数为 0 但确认添加过，检查 `hyperpguard_conf` 里是否还有 `custom_rules=` 这一项。

## 八、常见问题

| 现象 | 原因 |
|---|---|
| 添加后没有 `X(host)` | 没有重启对应应用 |
| 子域命中、主域没命中 | 规则写成了子域，主域请求的 host 不以该子域结尾 |
| 路径规则不生效 | 该请求没走 `URL#openConnection`，或「路径特征拦截」开关被关掉，或被规则写成了域名匹配不上的子域 |
| 某个包加了规则但没反应 | 该包属于上面四个「内置规则为空则不装载网络层」的组件 |
| 拦截后应用功能异常 | 命中了功能接口，删除该条规则并重启应用即可恢复 |
